# Обзор базы данных: одна запись о человеке

База данных учащихся строится вокруг **физического лица** — одной записи о человеке, к которой привязаны все его
роли: абитуриент, обучающийся, слушатель дополнительного образования, выпускник, сотрудник, плательщик по договору.
Это прямое следствие принципа «[Исключение дублирования](../../index.md)»: данные о человеке вносятся один раз
и используются во всех процессах. В таблице [статусов](list_of_status.md) это видно по колонке «Объект привязки»:
часть статусов относится к физическому лицу, часть — к обучающемуся (роли этого лица).

## 1. Почему дубли появляются и чем опасны

Один и тот же человек приходит в организацию многократно и из разных источников: подал заявление через
Суперсервис, учился на курсах ДПО три года назад, работает по совместительству, его данные пришли из кадровой
системы. Если каждый раз заводить новую запись:

- в отчётности (ФРДО, мониторинги) один человек считается дважды;
- история обучения и документы об образовании разрываются между записями;
- выплаты и расчёты по договорам уходят «не туда».

Обратная ошибка — **ложное слияние** двух разных людей (однофамильцы с одной датой рождения) — ещё опаснее:
чужие документы и оценки попадают в личное дело. Поэтому система должна **находить** возможные дубли, но
**сливать** записи только при достаточных основаниях.

## 2. Идентификаторы человека

Каждый известный номер человека хранится как отдельный идентификатор с указанием типа, страны выдачи и
нормализованного значения. Один номер принадлежит только одному человеку.

| Тип идентификатора | Область уникальности | Сила | Примечание |
|---|---|---|---|
| СНИЛС | страна | сквозной | проверяется контрольное число |
| ИНН физического лица | страна | сквозной | проверяются контрольные цифры |
| Национальный идентификатор иностранца (ИИН, ПИНФЛ и т.п.) | страна выдачи | сквозной | для иностранных граждан заменяет СНИЛС |
| Документ, удостоверяющий личность | страна выдачи | доказывает тождество только в пределах срока действия | история документов сохраняется: прежний паспорт тоже идентифицирует человека |
| Идентификатор во внешней системе | система | технический | номер записи в другой информационной системе — повторная загрузка данных не создаёт дублей |
| Единый идентификатор вуза (ЕИВ) | организация | собственный | присваивается каждому человеку, не меняется никогда; см. [API](../../about/api.md) |

**Нормализация** перед сравнением:

- ФИО: верхний регистр, «Ё» = «Е», дефисы и апострофы как пробелы, лишние пробелы убираются;
- номер документа: только буквы и цифры, кириллические буквы-двойники (А, В, Е, К, М, Н, О, Р, С, Т, У, Х) приводятся
  к латинским, граница серии и номера не важна: `4510 123456`, `45 10123456` и `4510123456` — один документ;
- телефон — к виду `+7…`, email — нижний регистр.

## 3. Ступени идентификации

Уровень достоверности записи вычисляется по набору известных идентификаторов и определяет, какие действия с ней
допустимы.

| Ступень | Что известно | Что разрешено | Как ищутся дубли |
|---|---|---|---|
| 0. Контакт | имя, канал связи | заявка, рассылка | как человек не дедуплицируется |
| 1. Заявленный | + дата рождения, пол | запись на мероприятие, тестирование | предупреждение при вводе, слияние запрещено |
| 2. Описанный | + место рождения, гражданство, контакты | договор на короткую программу без документа | кластеризация, слияние только вручную |
| 3. Документированный | + документ, удостоверяющий личность | договор, зачисление | связывание по документу в пределах срока действия |
| 4. Идентифицированный | + сквозной номер (СНИЛС, ИНН, национальный идентификатор) | программы с отчётностью в ФРДО, выдача документов об образовании | автоматическое связывание по совпадению номера |
| 5. Подтверждённый | + подтверждение через ЕСИА или сверка с ГИС | все действия, включая юридически значимые | приоритет подтверждённых данных при конфликте |

## 4. Поиск возможных дублей

Поиск выполняется **при вводе** новой записи и **при каждой загрузке** данных из других систем. Сравниваются:

| Совпадение | Вес | Как учитывается |
|---|---|---|
| Сквозной номер (СНИЛС, ИНН) | 100 | веса номеров и документов складываются |
| Документ, удостоверяющий личность | 60 | |
| Фамилия + имя + дата рождения (фонетически) | 50 | по ФИО и дате берётся **одно** сильнейшее совпадение: однофамильцы не должны набрать вес сквозного номера |
| Части имени в любом порядке + дата рождения | 40 | для имён без деления на фамилию и имя, иностранных имён |
| Дата рождения + инициалы | 30 | |
| Фамилия + год рождения | 20 | |

Сравнение имён — **фонетическое**: «Наталия» и «Наталья» совпадают, диакритика снимается (Fernández = Fernandez),
двойная фамилия сравнивается по первой части, служебные частицы (бин, аль, де, фон…) не учитываются.

Правила принятия решений:

- **разные корректные СНИЛС — разные люди**, сколько бы ни совпадало остальное;
- пара, которую человек отметил как **«подтверждённо разные»**, больше не предлагается;
- если номер, уже закреплённый за одним человеком, появился у другой записи, номер **не перезаписывается** —
  создаётся связь «конфликт» для разбора ответственным;
- объединение записей не удаляет запись: она помечается «объединена в», и все ссылки по её номерам
  переадресуются на сохранённую запись.

**Сигналы, требующие внимания (алерты).** Признаки, которые сами по себе не доказывают дубль, но требуют проверки:

- один и тот же банковский счёт указан у разных людей (возможно, один платит за другого — это нормально,
  но это должно быть видно ответственному);
- совпадение адреса электронной почты или телефона у разных людей (например, родительская почта у нескольких детей).

## 5. Приёмочные случаи

Модель проверяется на наборе реальных ситуаций; ни один из них не должен давать ложного автоматического слияния
и ни один не должен теряться.

| № | Случай | Что проверяет |
|---|---|---|
| 1 | Kumar, Индия, одно имя | необязательность фамилии |
| 2 | Wang Xiaoming / Xiaoming Wang | порядок частей имени |
| 3 | María del Carmen Fernández López | две фамилии, служебная частица |
| 4 | Мухаммад бин Абдулла аль-Фахри | цепочка имён без фамилии |
| 5 | Иванова → Петрова (брак на втором курсе) | имя во времени, диплом на прежнюю фамилию |
| 6 | Двое «Ивановых И.И.» с одной датой рождения | защита от ложного слияния |
| 7 | Слушатель ДПО без СНИЛС = абитуриент со СНИЛС | связывание «бедной» записи с «богатой» |
| 8 | Наталия → Наталья из кадровой системы | отличие опечатки от смены имени |
| 9 | Три ребёнка на одной родительской почте | общий канал связи |
| 10 | Иностранный паспорт: номер с буквами, без серии | унификация документов |

## 6. Загрузка данных из других систем

Перенос из других информационных систем (например, из прежней системы учёта контингента) идёт **через тот же
поиск дублей**, а не прямым копированием:

1. запись ищется по идентификатору во внешней системе — найдена: обновляется та же запись;
2. иначе выполняется поиск возможных дублей: совпал сквозной номер — запись связывается с существующей;
   средний вес — создаётся новая запись и ставится на проверку; иначе создаётся новая;
3. переносится вся история: прежние ФИО, прежние документы, гражданство.

Перед настоящим переносом выполняется **прогон «только журнал»**: отчёт о том, сколько записей будет создано,
связано, отправлено на проверку и сколько конфликтов (в том числе дублей внутри самого источника).

## 7. Источник истины

Информационная система вуза — **источник истины по физическому лицу**: идентификаторы, документы, банковские
счета и карты для выплат ведутся в ней и передаются в кадровую и бухгалтерскую системы. Кадровая система может
вносить изменения (например, при приёме на работу), но идентичность человека определяется по правилам этого раздела.
